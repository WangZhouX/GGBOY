# 策略金库

Anchor 程序 `ggboy_vault` 管理资产托管和份额。提供金库初始化、存入、现金赎回、测试策略兑换和借贷池联动，`ping` 用于检查程序入口。

## 初始化金库

`initialize_vault` 无指令参数。程序以预先创建的六位小数原版 SPL Token Mint 作为测试 USDC，由部署程序的当前升级权限持有人签名并支付账户创建费用。程序核对当前程序与 `ProgramData` 的对应关系和升级权限，以一笔交易创建以下三个账户。

| 账户 | PDA 种子 | 初始化结果 |
| --- | --- | --- |
| `vault` | `vault` | 每个程序部署一个金库，记录初始化管理员、结算 Mint、托管账户、份额 Mint 和金库自身的 PDA bump。 |
| `cash_vault` | `cash_vault`、金库 PDA | 金库专用的原版 SPL Token 账户，Mint 为测试 USDC，转账权限归金库 PDA，初始余额为 0。 |
| `share_mint` | `share_mint`、金库 PDA | 六位小数的原版 SPL Token Mint，表示 `GG-V`，铸造权归金库 PDA，未配置冻结权限，初始总供给为 0。 |

`GG-V` 是项目按 Mint 公钥使用的展示名称。钱包可识别的代币元数据需要独立登记。

## 存入测试 USDC

投资者签名调用 `deposit(assets_in, min_shares_out)`。两个参数分别是测试 USDC 存入量和最低可接受的 `GG-V` 份额，均使用六位小数的最小单位整数。扣款和收取份额的代币账户须事先创建，绑定对应的 Mint，且均由签名钱包拥有。接收账户可由客户端在同一交易的前置指令创建。

程序读取转账前的金库净值和份额 Mint 供给量。两者均为 0 时按 1:1 铸份，只有其中一项为 0 时拒绝存入。正常报价按 `存入金额 × 总份额 ÷ 金库净值` 向下取整。参数或算出的份额为 0、输出超出金额范围或低于最低份额时，均拒绝交易。检查通过后，程序在同一笔交易转入测试 USDC、以金库 PDA 权限铸造 `GG-V`，并通过 `VaultDeposit` 记录实际转入量和铸造量。

## 赎回测试 USDC

投资者签名调用 `redeem(shares_in, min_assets_out)`。两个参数分别是销毁的 `GG-V` 份额和最低接受的测试 USDC 到账量，均为六位小数的最小单位整数。两种代币账户须已创建、具有对应的 Mint 且均归签名者所有。

实际支付按 `输入份额 × 赎回前的金库净值 ÷ 赎回前的总份额` 向下取整。程序校验输入和输出均为正数，赎回份额在来源余额和总份额以内，支付金额达到最低到账。附加自动收回账户时，现金不足会先从金库的出借仓位提取，再由投资者授权销毁份额、由金库 PDA 授权转出现金，并发出 `VaultRedeem` 事件。最后一笔可同笔收回完整出借仓位，现货仍须已清空。失败会回滚池账本、现金与份额。

## 策略管理

管理员调用 `initialize_vault_strategy(manager, reserve_bps, lending_cap_bps, max_trade_bps)` 一次性开启已有金库的策略功能。它沿用原金库地址、管理员、现金账户和份额 Mint，保留 137 字节旧布局并增加一个字节用于识别已开启的金库。比例使用基点，最大交易比例须为 1 至 10000，留存和出借上限允许 0 至 10000。配置绑定债务 Mint 等于金库结算资产、抵押 Mint 等于九位小数测试 tSOL 的规范 GGBOY 借贷市场。

| 账户 | 金库程序 PDA 种子 | 代币权限 |
| --- | --- | --- |
| 策略配置 | `strategy`、金库 | 非代币账户，保存管理者和参数 |
| 策略托管 | `strategy_custody`、策略配置 | 金库 PDA |
| 测试兑换现金储备 | `swap_cash`、策略配置 | 策略配置 PDA |
| 测试兑换策略储备 | `swap_strategy`、策略配置 | 策略配置 PDA |

兑换前向两种测试储备补充对应测试代币。储备独立于投资者资金，金额不计入金库净值。程序只支持绑定的两种测试代币、规范储备和规范借贷市场价格。市场管理员发布的价格以每枚策略资产对应的结算 Mint 最小单位计，必须为正且处于 7 天有效期内。

| 指令 | 口径 |
| --- | --- |
| `strategy_swap` | 仅管理者签名。买入按结算输入金额限制单笔额度，卖出按当前价格折算的结算输出限制单笔额度。两腿按实时测试价格转移真实 SPL 余额，输出向下取整并校验最低到账。若正净值的比例上限舍入为零，允许卖出一个结算最小单位。 |
| `strategy_lend` | 仅管理者签名。现金减 `ceil(净值 × 留存基点 / 10000)` 和 `floor(净值 × 出借上限基点 / 10000)` 减现有出借估值的较小值为额度，低于 0 时按 0 处理。管理者支付首笔创建租金，现金和获得的出借份额均归金库。 |
| `strategy_recall` | 仅管理者签名。按份额收回，借贷程序检查金库持有的份额、已记账可用现金及最低到账。即使策略价格失效也可收回贷款现金。 |

管理者可调用 `clear_strategy_dust`，在有效报价确认整笔正数策略余额低于一个结算最小单位时，将尾仓全部移入绑定测试储备并记录 `VaultStrategyDustCleared`。该清理仅处理不可变现尾仓，有正常报价的仓位继续走卖出指令。

三条策略资金指令在资金转移成功后发出 `VaultStrategyAction`，记录签名管理者、金库、方向与实际转移数量。

策略打开后，存赎指令原有账户和指令参数继续使用，同时附加策略配置、策略托管、规范市场、价格、池记账与金库出借仓位六个只读账户，按此顺序传入。策略为空仓时其估值为零。非空策略持仓需要有效价格。净值为现金加策略资产按价格换算值与金库池份额估值，分项以结算资产最小单位向下取整。原先纯现金的金库继续以原有账户列表运行。

### 赎回时自动收回

新版金库的策略初始化会设置 138 字节金库状态末尾第 137 字节（零基）的最低位。旧版策略金库升级程序后，由原金库管理员用 `enable_auto_recall` 通过规范策略配置设置该位，重复调用保持原账户内容。功能位开启后，赎回可追加借贷池现金托管、规范借款账本 PDA、借贷程序，依次为第七至第九个附加账户。池记账、金库出借仓位和借贷池现金托管须可写。其余估值账户与现有六账户调用相同。纯现金金库沿用原调用，已启用策略但仅传六个账户时按金库已有现金结算。

若金库现金低于报价，普通赎回收回的份额为 `ceil(所缺现金 × 池总份额 ÷ 池总记账资产)`。借贷程序按操作前池份额比例向下取整支付，检查提取量和最低到账，并校验实际托管现金及扣除未偿债务后的账面现金。若舍入使收回额超过所缺现金，余款留在金库中。全额赎回时须收回金库全部出借份额，并且已有策略现货为零。如果完整出借仓位折算为零，只在最后一笔退出时由借贷程序注销零价值份额。管理员仍可通过 `strategy_recall` 恢复现金，再由原客户端赎回。

测试兑换位于金库程序中，使用隔离的储备账户。面向真实资产的 Jupiter CPI 需要独立的接入和验收。
